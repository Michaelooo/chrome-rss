# Chrome RSS Reader

一个现代化的 Chrome RSS 阅读器插件，灵感来自 Feedbro，使用最新的 Manifest V3 规范构建。

## 功能特性

### 核心功能
- RSS/Atom Feed 订阅管理
- 三栏式高效阅读界面（Feed列表 - 文章列表 - 阅读器）
- 文章已读/未读状态管理
- 文章收藏功能（星标）
- 后台自动更新 Feed
- 通知提醒新文章
- 搜索文章功能
- 浅色/深色主题切换（即时生效，支持跟随系统）

### AI 功能
- **文章摘要与阅读洞察**：生成结构化摘要、标签、重点原文依据、文章质量和阅读建议
- **全文与标题翻译**：支持 AI 分段翻译和 Google 翻译，可切换原文、中译与双语视图
- **每日简报**：自动生成每日简报，按重要性（高/中/低）分类
- **多服务商容错**：配置一个主服务商和多个有序备用服务商；遇到网络错误、超时、限流、服务端错误或无效响应时按顺序尝试备用服务，鉴权和其他不可重试错误不会自动切换
- **服务商基准测试**：使用固定的摘要与翻译样本，比较各服务商的响应耗时、结构完整度、事实/术语锚点和 JSON 格式
- **快速切换主服务商**：可从基准测试结果中将已启用的备用服务商设为主服务商，并完整交换服务商配置

### 过滤规则
- 按标题/内容/作者/链接设置过滤条件
- 支持正则表达式匹配
- AND/OR 逻辑组合
- 动作：标记已读、加星、删除、添加标签
- 支持全局规则和按订阅源规则

### 数据管理
- IndexedDB 本地存储，支持离线访问
- OPML 导入/导出
- 全文抓取功能
- 智能更新策略（可配置更新间隔）
- 文章自动清理（可配置保留时间）
- 存储空间管理

### 界面特性
- 现代化设计，简洁高效
- 虚拟滚动，支持海量文章
- 可调整栏宽的三栏布局
- 键盘快捷键支持
- 中英文双语支持

## 技术栈

- **前端框架**: React 18 + TypeScript
- **构建工具**: Vite + @crxjs/vite-plugin
- **样式**: TailwindCSS
- **状态管理**: Zustand
- **数据库**: IndexedDB (Dexie.js)
- **UI 组件**: Radix UI
- **图标**: Lucide React

## 安装说明

### 开发环境

1. 克隆仓库并安装依赖：
```bash
pnpm install
```

2. 开发模式（基于 `@crxjs/vite-plugin` 的热更新）：
```bash
pnpm dev
```
   - React 页面（main / popup / options）支持模块热替换（HMR），状态保留
   - 修改 Service Worker 或 `manifest.json` 时扩展会自动 reload，无需手动刷新

3. 构建生产版本：
```bash
pnpm build
```

### 加载到 Chrome

#### 开发模式
1. 运行 `pnpm dev`，等待首次写入 `dist/`
2. 打开 `chrome://extensions/`，开启"开发者模式"
3. 点击"加载已解压的扩展程序"，选择 `dist/` 目录（只需加载一次）
4. 之后改代码会自动同步到扩展，无需重复加载

#### 生产模式
1. 构建项目：`pnpm build`
2. 在 `chrome://extensions/` 中加载 `dist/` 目录

## 使用指南

### 添加 Feed
点击侧边栏 ➕ 按钮，输入 RSS Feed URL

### 阅读文章
左侧边栏选择 Feed → 中间栏点击文章 → 右侧阅读器显示内容

### 过滤规则
侧边栏点击漏斗图标，创建过滤规则。支持按标题、内容、作者、链接设置条件，支持正则和逻辑组合。

### 设置
点击工具栏设置按钮。设置页按“通用”“订阅与存储”“阅读体验”“翻译与洞察”“AI 服务”分类；桌面端使用左侧导航，移动端使用顶部分类栏，并支持通过页面锚点直接定位。

### 服务商基准测试
在“AI 服务”中可选择快速或标准测试：快速模式对每个服务商执行 1 次摘要和 1 次翻译，标准模式各执行 3 次。请求串行执行且启动间隔至少 3 秒；每个服务商独立测试，不会触发备用服务回退。

测试分数基于固定样本，只检查 JSON、字段/块完整度、事实锚点和术语保留，不代表模型在所有任务上的准确率、安全性或生产稳定性。结果和最多 1000 字符的输出预览仅保留在当前设置页会话中，关闭或刷新页面后消失；服务商自身仍可能按其政策记录请求。

## 数据存储与外部服务

- 订阅、文章、文件夹、规则、AI 产物、设置和 AI API Key 保存在扩展本地的 IndexedDB 中，不使用项目自建的云端同步。
- API Key 在 IndexedDB 中没有应用层加密。本地持久化不等于不会发生网络传输，请只在可信设备上使用。
- 使用 AI 摘要、翻译、阅读分析或简报时，可能包含文章标题和正文的请求内容，以及对应 API Key，会发送到你配置的 OpenAI 兼容第三方 Endpoint。请查阅该服务商的隐私和数据留存政策。
- 使用 Google 翻译时，待翻译文本会发送给 Google 的翻译服务。
- 远程 AI 服务建议只使用可信的 HTTPS Endpoint。不要通过远程明文 HTTP Endpoint 发送敏感 API Key 或文章内容。

## 常见问题

### Q: 支持哪些 Feed 格式？
A: 支持 RSS 2.0 和 Atom 1.0 格式。

### Q: 数据和 AI API Key 存储在哪里？
A: 订阅、文章、设置和 AI API Key 保存在扩展本地的 IndexedDB 中，不使用项目自建的云端同步。API Key 在本地没有应用层加密；启用 AI 或 Google 翻译功能时，完成操作所需的内容会发送到对应第三方服务。

### Q: AI 功能如何使用？
A: 在设置页的“AI 服务”中配置 OpenAI 兼容的 API 地址、Key 和模型。可添加有序备用服务商，并运行固定样本基准测试；基准测试单独调用每个服务商，不会自动回退到其他服务商。远程服务请优先使用 HTTPS Endpoint。
